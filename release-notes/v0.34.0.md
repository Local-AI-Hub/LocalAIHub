# v0.34.0 — Chatterbox voice TTS, TripoSR launch, and Wan readiness

## Highlights
- Added Chatterbox-Turbo Reference Voice TTS as a managed local audio pipeline path.
- Integrated Chatterbox-TTS-Server as the Chatterbox Library/WebUI surface while preserving the direct helper-backed pipeline path.
- Fixed and hardened TripoSR/Trellis Library launch readiness and repair validation.
- Made Wan Library readiness honest with explicit model, CUDA, VRAM, RAM, and dependency diagnostics.
- Exposed Wan and TripoSR/Trellis launch readiness verifiers as npm release sanity scripts.

## Chatterbox-Turbo Reference Voice TTS
- Added Chatterbox-Turbo as a managed local audio tool.
- Added Model Step Audio Generate / Reference Voice TTS mode for Text Input + Audio Input reference voice -> Model Step Chatterbox-Turbo -> Audio Output pipelines.
- Added the `run_chatterbox_tts_task.py` helper.
- Uses Python 3.11, CUDA torch==2.6.0+cu124, torchaudio==2.6.0+cu124, chatterbox-tts==0.1.7, and setuptools<81.
- Added CUDA-first runtime behavior with plain-English errors for missing CUDA, CUDA OOM, missing packages, Hugging Face/cache failures, pkg_resources/setuptools issues, missing text, missing reference audio, and too-short reference audio.
- Added a reference voice consent/rights warning in the Pipeline Builder UI.
- Added `.audio.json` sidecar metadata for referenceVoiceTts outputs, including reference audio lineage, tool/model, sample rate, duration, channels, device/GPU, package versions, text length, and peak VRAM metrics.
- Live helper smoke test succeeded on GTX 1060 6GB.
- Manual pipeline test succeeded and produced speech in the reference voice.

## Chatterbox WebUI launch
- Integrated devnen/Chatterbox-TTS-Server as the Library/WebUI surface for Chatterbox-Turbo.
- Preserved the direct helper-backed Pipeline Builder path as the production path.
- Added server source install pinned to a known commit.
- Added managed WebUI dependencies and generated launch shim.
- Library launch binds to localhost on managed port 8004 and waits on `/api/ui/initial-data`.
- Added bundled FFmpeg launch environment for WebUI audio utilities.
- Added runtime recovery messages for Chatterbox WebUI failures.
- Added consent/rights note to Chatterbox Store/Library cards.
- Manual Library launch test succeeded after repair and opened the WebUI.

## TripoSR/Trellis launch fixes
- Fixed stale launch args for the installed TripoSR Gradio launcher.
- Added dependency pins for the Gradio/FastAPI/Starlette/Uvicorn/Pydantic web stack.
- Added ONNX Runtime installation and validation.
- Added install/repair finalization checks for ONNX Runtime, torchmcubes, and the pinned web stack.
- Added runtime recovery classifications for missing ONNX Runtime and incompatible TripoSR web stack.
- Added `verify-triposr-launch-readiness.js`.
- Manually validated Library launch after repair.

## Wan readiness and diagnostics
- Made Wan Library readiness honest instead of optimistic.
- Updated Wan launch command to pass the managed checkpoint directory.
- Added preflight checks for missing app folder, missing Wan model folder, low VRAM/RAM, and CUDA/PyTorch readiness.
- Added install/repair runtime verification for Torch, Gradio, DiffSynth, Transformers, Pillow, NumPy, and CUDA-backed PyTorch availability.
- Added runtime recovery classifications for missing DiffSynth, DashScope/prompt-expander failures, missing Wan model assets, insufficient VRAM, and CUDA OOM.
- Added `verify-wan-launch-readiness.js`.
- Preserved existing Model Step video generation and collectionMap video paths.
- Manual validation on a GTX 1060 machine confirmed Wan now fails with a precise readiness/install message instead of a misleading launch failure.

## Release verification hardening
- Added npm scripts `verify:wan-launch` and `verify:triposr-launch`.
- Release sanity included manifest verification, Wan and TripoSR/Trellis readiness verifiers, managed launch storage verification, Model Step node verification, audio pipeline verification, local video pipeline verification, collection map verification, InvokeAI readiness verification, image transform verification, UI build, and full Electron build.

## Verification and known limitations
- Wan video generation paths remain untested on the current hardware.
- Wan Library launch on a fully capable CUDA system with required model assets remains untested.
- TripoSR/Trellis generation remains untested; Library launch is validated.
- Chatterbox voice cloning should only be used with voices the user has permission to use.
- Hugging Face model/cache downloads may require network access and can hit external rate limits.

## Deferred items
- Chatterbox collectionMap support is intentionally deferred.
- Wan full generation and collectionMap text-to-video / previous-last-frame chaining remain untested due to hardware limits.
