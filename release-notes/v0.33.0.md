# v0.33.0 — RVC, image transform tools, and InvokeAI integration fixes

## Highlights
- Fixed RVC Model Manager downloads, discovery, repair completeness, and audio-to-audio pipeline execution.
- Fixed FaceFusion repair, launch environment, runtime recovery, and image-transform output handling.
- Fixed Upscayl image-transform pipeline execution, including correct CLI selection, timeout, and cancellation handling.
- Updated InvokeAI launch/readiness for InvokeAI 6.12.0 and added selected Model Manager support.
- Fixed InvokeAI Graph Workflow API execution paths for the current InvokeAI queue, image upload, and image retrieval APIs.

## RVC Model Manager and pipeline fixes
- Accept valid Hugging Face `.pth` voice models as required primary RVC artifacts while preserving optional `.index` companion handling.
- Prevent serialized UI download plans with empty `downloadFiles` arrays from being misrouted into package installs.
- Align RVC Model Step discovery/runtime paths with Model Manager downloads.
- Discover `.pth` and `.pt` models in the managed RVC weights layout, including nested and repo-specific subfolders.
- Attach optional `.index` metadata when confidently matched.
- Remove unsupported RVC `--listen` launch args and use supported launch behavior.
- Run the RVC pipeline through the direct helper path instead of starting the WebUI unnecessarily.
- Make bundled FFmpeg available to RVC helper execution.
- Improve diagnostics for missing FFmpeg, missing Hubert/RMVPE assets, backend tracebacks, and incomplete outputs.
- Repair/install now restores `assets/hubert/hubert_base.pt`, restores `assets/rmvpe/rmvpe.pt`, pins a compatible `gradio_client` for Gradio 3.34, and validates runtime assets/dependencies honestly.
- Fix `torch.load` checkpoint compatibility for normal RVC `.pth` checkpoints.

## FaceFusion repair/launch/pipeline fixes
- Fix repair/install dependency completeness for `cv2`, `numpy`, and `onnxruntime`.
- Add per-tool install/repair locking to avoid overlapping repair attempts corrupting active dependency installs.
- Make bundled FFmpeg available on `PATH` and through FFmpeg environment variables during launch.
- Add runtime recovery classification for missing OpenCV, onnxruntime, and FFmpeg issues.
- Match output extension to the target image extension as required by FaceFusion.
- Filter progress-only lines from final error summaries while preserving backend diagnostics.
- Require a non-empty transformed image when validating FaceFusion image outputs.

## Upscayl pipeline transform fixes
- Fix the Upscayl Model Step image-transform hang caused by selecting the desktop app executable instead of the bundled Upscayl CLI binary.
- Resolve the correct CLI executable for pipeline transforms.
- Add stage logging, timeout handling, and cancellation/abort handling for active Upscayl transform commands.
- Allow Cancel Run to terminate the active child process tree.
- Preserve existing Library launch behavior.

## InvokeAI launch/readiness
- Update launch for installed InvokeAI 6.12.0 from the stale `python -m invokeai.app.run_app` path to `invokeai-web.exe --root ... --config invokeai.yaml`.
- Update readiness checks to `/api/v1/app/version`.
- Add a post-ready check for missing web UI assets.
- Improve InvokeAI startup diagnostics.

## InvokeAI Model Manager support
- Add InvokeAI as a Model Manager target.
- Import models through InvokeAI's own API with `POST /api/v2/models/install?source=<local-temp-file>&inplace=false` instead of unsafe copy-only placement.
- Add selected single-file support for checkpoints, inpainting checkpoints, LoRA, ControlNet, VAE, and textual inversion/embedding artifacts.
- Use InvokeAI's registered model API for downloaded model listing when available.
- Use InvokeAI unregister/remove behavior for delete operations instead of blind file deletion.

## InvokeAI Graph Workflow execution
- Use the current InvokeAI 6.12 API flow for graph execution: enqueue batch, poll batch status, inspect queue item results, download final images, and upload image inputs.
- Fix stale routes missing the `/api` prefix that caused Method Not Allowed errors.
- Hydrate model metadata before enqueue so incomplete model references can be resolved through `/api/v2/models`.
- Preserve text input mapping to InvokeAI batch data substitution, including fields such as `positive_prompt.prompt`.
- Create Local AI Hub image artifacts from completed InvokeAI queue/session image results.
- Improve InvokeAI API errors for method/route mismatches, validation errors, and failed graph execution.
- Preserve the existing ComfyUI Graph Workflow execution path.

## Verification and known limitations
- Targeted verifiers were preserved and updated for RVC, FaceFusion, Upscayl, InvokeAI, image backend, Model Manager, and audio pipeline coverage.
- RVC audio-to-audio pipeline was manually validated successfully.
- FaceFusion Library launch and image-transform pipeline were manually validated successfully.
- Upscayl enhance and upscale Model Step pipelines were manually validated successfully.
- InvokeAI Library launch was manually validated successfully.
- InvokeAI Model Manager manually imported and registered `stable-diffusion-v1-5` through Local AI Hub.
- InvokeAI Graph Workflow API execution is fixed, but full generation may still exceed low-VRAM hardware. A local graph generation test progressed past parsing, submission, and runtime setup, then crashed the test PC after several minutes, likely due to hardware/resource exhaustion.
- Hugging Face 429/rate-limit responses encountered during manual browsing/testing are external service throttling, not a Local AI Hub defect.

## Deferred items
- InvokeAI diffusers folder/package imports, Flux/Qwen/SD3 family-specific flows, IP Adapter, refiner flows, upscalers, hypernetworks, and complex multi-file packages remain deferred.
- TripoSR/Trellis and Wan launch fixes are not included in this release and remain deferred for future work.
